# Continuous Soft Reweighting For PR–KL Consistency Distillation

## Original Idea

文章https://arxiv.org/pdf/2605.03677中针对KL散度打分和结果的一致性，来校验这个KL打分是否合理。在这个基础上，我们分析了KL散度打分在一个回答中不同段落中的一致性问题。student 在 rollout 过程中，某些推理段落虽然获得了较高的 Process Reward（PR），但与 teacher 的分布一致性（KL）反而更差。如果直接对所有 token 做 KL 蒸馏，可能会引入错误的监督信号，影响训练质量。

针对这个问题，我设计了一套基于 PR–KL 序关系的一致性筛选机制，核心思路是：

不把 PR 当作回归目标，而是作为判断 KL 是否可靠的序探针；

在同一 response 内，要求 PR 高的段落，其 KL 应更低（与 teacher 更一致）；

对违反这一关系的段落，在 OPD loss 中将其 token 权重置零（mask），避免污染训练；
同时，对整体不可靠的 response 进行重试或丢弃，逐步构建高质量训练集。

pr的计算方式为：#### Step 1: Student rollout
- prompt: `build_filter_prompt(problem, tokenizer)` → `[sys: EPISODE_EVAL_SYSTEM][user: problem]` + `add_generation_prompt`
- 采样: temperature=ROLLOUT_TEMPERATURE, top_k=50, n=1, max_tokens=MAX_NEW_TOKENS
- 通过 `safe_generate`（带 prompt 长度过滤、失败兜底）

#### Step 2: 段落切分（CPU）
`segment_response_text(response)`：
- 在 trigger word（如 "wait", "let me check", "actually"...）处切，且当前段累计句号数 ≥ `SEGMENT_MIN_PERIODS` 才切
- 返回 `[(start_char, end_char), ...]`，episode i 的前缀 = `response[:end_char]`

#### Step 3: K-fold PR 评估
对每条 student response，构建一组 forced-answer prompt：
- **Empty-prefix baseline**: `build_episode_eval_prompt(problem, "", tok)` → 学生不思考、直接强制出 boxed 答案的命中率
- **每个 episode 边界**: `build_episode_eval_prompt(problem, response[:end_c], tok)` → 截到第 i 段末尾后强制出答案的命中率

每条 prompt 采样 `K_EVAL` 次（temperature=EVAL_TEMPERATURE, max_tokens=MAX_ANSWER_TOKENS, stop=`<|im_end|>`）。
每条 prompt 的 acc_rate = K 次中命中 gt 的比例。

`build_episode_eval_prompt` 关键细节：如果 prefix 在 `<think>` 块内，先补 `</think>` 再加 `EPISODE_EVAL_SUFFIX`（强制收敛到 boxed 答案）。

K-fold 结果存进 `acc_per_li[li] = {-1: empty_acc, 0: acc_0, 1: acc_1, ...}`。

#### Step 4: 计算 PR + 段权重 + 写训练记录

`compute_segments_for_response(episodes, ep_accs, empty_acc, do_merge)`：

1. **原始 PR**: 对每段 i，`pr_i = acc_rate_i - acc_rate_{i-1}`（i=0 时上一段 = `empty_acc`）
2. **可选 merge**: 若 `MERGE_SEGMENTS=true`，调 `merge_monotonic_runs` 折叠 PR 单调 run（连续上升或连续下降 → 合并为最末端那个点）
3. **重算 PR**（合并后）: 用「相对 empty_acc 的累积变化」重算，即 `pr_merged_i = acc_merged_i - acc_merged_{i-1}`

## Primary Direction: Continuous Soft Reweighting

### Rationale

Replace the binary paragraph mask with a smooth per-paragraph (or per-token) weight derived from the local PR–KL ordering agreement, so the OPD loss continuously down-weights inconsistent paragraphs without a cliff-edge threshold and without dropping any gradient information; this is the soft-and-continuous antipode of the binary-mask scheme and slots into the existing per-token `response_weights` pipeline with the smallest possible delta.

### Approach Summary

Within the existing `tools/process_reward_consistency_opd.py` pipeline, replace the binary mask in `_consistency_dispatch` (which today writes `weights[j] = 0.0` for masked spans and `1.0` elsewhere, via the `mask_indices` set fed by `_score_response_paragraphs`) with a continuous, monotonically-decreasing function of each paragraph's per-paragraph inconsistency score:

1. **Keep `_score_response_paragraphs` as the source of inconsistency**: it already returns a per-paragraph `inconsistency[i]` array computed as the sum of magnitude-weighted neighbor violations `max(0, KL_A − KL_B) × max(0, PR_A − PR_B)` the paragraph participates in.
2. **Normalize within a response** with a min-max or quantile transform (precedent: `gkd_softor_trainer.py:s_t = h̃_t + δ̃_t − h̃_t × δ̃_t` lines 4–18, where per-batch min-max normalises entropy + KL into [0,1] before combining). Call the normalised value `incñ_i ∈ [0,1]`.
3. **Map to a weight** via a single-parameter smooth gate, for example
   `w_i = (1 − incñ_i)^γ`  or  `w_i = σ(α · (τ − incñ_i))`,
   where γ (or α, τ) is a config-level knob added to a new `consistency_opd_config` block. As γ → ∞ this recovers the existing binary mask; as γ → 0 it recovers vanilla OPD; γ ≈ 1 gives a linear soft fall-off.
4. **Write continuous `response_weights`** into the train JSONL exactly as today (`process_reward_consistency_opd.py:1963, 1994` already write a per-token `weights = [1.0] * resp_len` then assign `weights[j] = 0.0`; the assignment becomes `weights[j] = w_i` for token j in paragraph i).
5. **Consume in the OPD loss unchanged**: the in-file trainer at `process_reward_consistency_opd.py:2364` (`OPD loss with top-K teacher support (CACHED) and per-token weights`) already does `weighted KL using student logits + cached teacher topk` with arbitrary `wts_flat` and `w_sum`. It does not need to know whether weights are {0, 1} or [0, 1]. The forward pass plumbing at lines 2410, 2443 (`wts = inputs.pop("weights")`) is unchanged.
6. **Replace `MASK_TOP_PERCENT_SEGMENTS` with `INCON_SOFTNESS` (or `SOFT_GAMMA`)** as the sole new knob. `TOP_PERCENT_RESPONSES` and `MAX_RETRIES` remain valid for response-level filtering — the soft weight only governs the within-response gradient flow.
7. **Validation**: add a fast regression test where γ ≫ 1 reproduces the existing binary-mask numerics within float tolerance, so the soft variant is a strict generalization.

The change is concentrated in two files: the scoring + record-writing pass in `tools/process_reward_consistency_opd.py` (~30 lines around `_consistency_dispatch` and the JSONL emit block at 1963–2030), and a new env var declaration near line 266 alongside `MASK_TOP_PERCENT_SEGMENTS`. No change to the in-file OPD trainer, no change to `swift/rlhf_trainers/gkd_trainer.py`, no change to dataset / collator / vLLM pipelines.

### Known Risks

- **Smearing the signal**: a smooth gate keeps a small gradient on highly-inconsistent paragraphs that the binary mask would zero. If those paragraphs are catastrophically bad (e.g., teacher distribution wrong + PR estimate noisy in opposite direction), the residual gradient could outweigh the gain from finer dose-response in the moderately-inconsistent region. Mitigation: pick γ via the regression test that recovers binary at large γ, and sweep γ ∈ {0, 1, 2, 4, 8, ∞}.
- **Hidden coupling with `TOP_PERCENT_RESPONSES`**: today the response-level filter (top 30% by `consistency_ratio = n_consistent / n_pairs`) already drops the worst responses entirely. If the soft weighting is added on top, the effective dose curve depends on which responses survive the response-level filter — sweep them jointly.
- **Per-paragraph normalisation is local**: min-max within a single response makes the weights non-comparable across responses; a paragraph with the lowest within-response inconsistency always gets `w = 1` even in a globally inconsistent response. Quantile-normalising against an epoch-wide inconsistency histogram is an alternative but adds a synchronization step.
- **No clean response-drop semantics**: the binary mask interacts cleanly with `n_kept_with_masks` / `n_vanilla_fallback` accounting (`tools/process_reward_consistency_opd.py:~1955`). With continuous weights, "fully consistent" becomes a continuum and these counters need re-definition (e.g., "fraction of kept responses with mean(w) > 0.9").
- **Regression to vanilla OPD if γ small**: a soft variant invites users to set γ low and effectively undo the filter; the train log should always report `mean(w_i over labelled tokens)` per epoch as a guard.

### Confidence

high

## Alternative Directions Considered

### Alt-1: Pairwise Magnitude-Weighted Violation Mask (status quo)

- Gist: Per response, sort merged paragraphs by PR descending, compute the adjacent-pair violation `max(0, KL_A − KL_B) × max(0, PR_A − PR_B)`, aggregate into per-paragraph inconsistency scores, then act in two stages: (a) drop responses below the top `TOP_PERCENT_RESPONSES`% by consistency ratio (with `MAX_RETRIES` retry semantics for student-wrong responses, discard for student-correct ones); (b) within kept responses, hard-mask up to `MASK_TOP_PERCENT_SEGMENTS`% of paragraphs whose inconsistency > 0 by setting their per-token `weights = 0.0`. Already implemented end-to-end in `tools/process_reward_consistency_opd.py` (3305 LOC) including the in-file OPD trainer at line 2364, the teacher top-K cache at line 73, the retry / discard / drop bookkeeping at line 2066, and distribution trackers (`n_kept_all_zero`, `n_kept_with_masks`, `n_vanilla_fallback`) for masking-machinery health.
- Objective Evidence:
  - `tools/process_reward_consistency_opd.py:1-169` — full design rationale and per-step pipeline doc.
  - `tools/process_reward_consistency_opd.py:835-879` (`_score_response_paragraphs`) — pairwise violation rule.
  - `tools/process_reward_consistency_opd.py:1825-2030` (`_consistency_dispatch`) — kept/retry/discard routing + paragraph masking.
  - `tools/process_reward_consistency_opd.py:266-274` — env-var knobs (`TOP_PERCENT_RESPONSES=30`, `MASK_TOP_PERCENT_SEGMENTS=20`, `MAX_RETRIES=3`).
  - `tools/process_reward_consistency_opd.py:2364-2452` — in-file OPD trainer consuming per-token weights.
  - `tools/analyze_pr_kl_merged.py` — the analysis that motivated the scheme (Pearson + Spearman per category).
- Why not primary: this direction IS the current implementation; the primary direction differs only by replacing the {0, 1} weight assignment at line 1982 with a smooth `w_i ∈ [0, 1]`. Promoting status quo as primary would convert the draft into a tuning exercise rather than a new mechanism.

### Alt-2: Per-Response Rank-Correlation Gate

- Gist: Collapse the within-response PR–KL signal into a single Spearman ρ (or Kendall τ) between the merged paragraph's PR vector and `−normKL` vector. Use one threshold τ_keep on ρ: above → train all paragraphs unmasked; below → drop response (retry/discard like today); optionally a soft mid-band. Replaces two coupled knobs (`MASK_TOP_PERCENT_SEGMENTS`, `TOP_PERCENT_RESPONSES`) with one threshold that has a known null distribution (two-sided p-value via `scipy.stats.spearmanr`) and admits multiple-comparison correction across an epoch.
- Objective Evidence:
  - `tools/analyze_pr_kl_merged.py:1112-1156` — already imports `scipy_stats.pearsonr` and `scipy_stats.spearmanr`; helper functions `_pearsonr`, `_spearmanr` exist and report `(r, p)` tuples; the analysis tool already computes ρ per category and per overall sample, but NOT per-response — exactly the surface this direction would add.
  - `tools/process_reward_consistency_opd.py:835-879` — the existing `consistency_ratio = n_consistent / n_pairs` over adjacent rank pairs is NOT Spearman ρ: it ignores rank distance and is local to adjacent pairs only. A genuine Spearman ρ replacement is a different statistic with different power.
  - `tools/process_reward_consistency_opd.py:266-274` — `TOP_PERCENT_RESPONSES` and `MASK_TOP_PERCENT_SEGMENTS` env vars that would be replaced by a single τ_keep.
- Why not primary: loses the within-response paragraph-level recovery — a response with one bad paragraph and many good ones would either be kept whole (lower precision) or dropped (lower recall). The continuous-weight primary preserves this recovery while still smoothing the cliff.

### Alt-4: Cheap Per-Token PR Proxy (Skip K-Fold Rollout)

- Gist: Replace the per-segment K-fold rollout (`K_EVAL=8` forced-answer samples × `(1 + n_episodes)` per response, the dominant compute cost in Step 3) with a cheap per-token surrogate computable directly from teacher / student logits already gathered in the KL phase: candidates include teacher NLL curvature `Δ(−log q(y_t | y_<t)) − Δ(−log q(y_{t−1} | y_<t−1))`, student-teacher top-1 disagreement, or a small value head trained on K-fold labels during a warmup epoch. This (a) reduces rollout cost by ~K×, (b) enables per-token (rather than per-paragraph) PR–KL alignment, and (c) breaks the dependency on the trigger-word segmenter for the PR signal.
- Objective Evidence:
  - `tools/process_reward_consistency_opd.py:152` — `K_EVAL = 8` per segment per response is documented as the K-fold count; in Step 3 this is the dominant vLLM cost.
  - `swift/rlhf_trainers/gkd_softor_trainer.py:1-30` — full precedent for per-token, logit-derived continuous scores (Soft-OR `s_t`) replacing rollout-based ones.
  - `swift/rlhf_trainers/gkd_confidence_trainer.py:1-50` — second precedent (entropy ratio `H_t / max(H_s, ε)`).
  - `swift/rewards/prm.py:1-156` — the repo's only PRM is API-based (Qwen-Max via DashScope), with no learned per-token head. Building a small in-process value head would be a net-new component.
  - `tools/episode_eval.py`, `tools/process_reward_distill.py` — existing K-fold mechanism that the proxy would replace, plus a calibration target to validate the proxy against.
- Why not primary: substantial new ML risk — the proxy may not correlate strongly enough with K-fold PR to make the consistency gate meaningful, and validation requires a side-by-side run against the K-fold ground truth. Primary direction takes the existing PR signal and improves the act-on-it side, which is the smaller bet.

### Alt-5: Noise-Aware Bayesian / Conformal Gate

- Gist: K-fold PR over `K_EVAL=8` Bernoulli samples has standard error up to ≈ 0.18 at `p=0.5`; the current violation rule `max(0, KL_A − KL_B) × max(0, PR_A − PR_B)` uses point estimates and has unknown false-positive rate. Model PR with a Beta-Binomial posterior (Beta(1 + k, 1 + K − k) from the `acc_per_li` dict already on disk), KL with an empirical-width normal, and gate violations by the posterior probability `P(true PR_A > true PR_B AND true KL_A > true KL_B) > τ`. Optionally calibrate τ on a held-out conformal set of "known consistent" responses so the false-positive masking rate is bounded.
- Objective Evidence:
  - `tools/process_reward_consistency_opd.py:835-879` — current violation rule uses point estimates with no variance term; the modification site is one function.
  - `tools/process_reward_consistency_opd.py:~152` — `acc_per_li[li] = {-1: empty_acc, 0: acc_0, ...}` already stores per-segment hit counts; deriving Beta(α, β) parameters needs only the K-fold raw counts, which are reachable from the same data structure.
  - No precedent in the repo for `scipy.stats.binomtest`, `beta`, `dirichlet`, conformal libraries, or posterior gates (verified by grep across `tools/` and `swift/`). This direction is therefore the most exploratory.
  - `tools/analyze_kl_heatmap.py`, `tools/analyze_pr_kl_merged.py` — supporting analysis tools that could be extended to plot the empirical CDF of violation magnitudes and validate the conformal calibration.
- Why not primary: highest theoretical appeal but largest new statistical machinery; needs a held-out calibration set design and adds a `scipy.stats` runtime dependency to the data pipeline. Primary direction is implementable without any statistical-modelling commitment.

### Alt-6: Inconsistency-Driven Curriculum Routing

- Gist: Use the PR–KL consistency score not as a token weight but as a router that sends each sample to one of four supervision modes — `high consistency → vanilla on-policy OPD on the full response`; `mid consistency → paragraph-masked OPD (the status-quo D1 pathway)`; `low consistency + student wrong + teacher correct → off-policy SFT on the teacher trajectory`; `low consistency + both wrong → discard or retry`. This generalises the existing 3-branch design in `tools/process_reward_distill.py` (PR-segment / teacher / discard) by adding consistency as a fourth axis, and notably re-introduces the teacher-trajectory SFT branch that `process_reward_consistency_opd.py` does not currently maintain.
- Objective Evidence:
  - `tools/process_reward_distill.py:28-30, 1402-1469` — existing 3-branch router and the three `train_records.append(...)` sites (PR-segment branch, teacher branch when `teacher_correct`, discard branch). Direct template for an extended router.
  - `mynote.md:54-71` — project author's own documentation of the existing 3-branch design and per-branch rationale.
  - `tools/process_reward_consistency_opd.py:2066` — existing retry-and-drop logic with `MAX_RETRIES`; the curriculum router adds three more terminal branches but reuses this state machine.
  - `swift/rlhf_trainers/gkd_trainer.py:280, 481-590` — `compute_loss` / `training_step` already discriminate between on-policy (`seq_kd`, `_opsd_teacher_inputs`) and off-policy (`encode_prompt_only=False`) batches; mixing the two within one DataLoader is feasible at the trainer level via the existing `DataSource` tag (`encoded_inputs['_data_source']`).
  - `tools/process_reward_correction_distill.py`, `tools/process_reward_weighted_distill.py` — sibling pipelines exploring alternative training-data formulations; the curriculum direction is the natural unifying frame.
- Why not primary: substantially larger surface (router state machine + per-branch sample accounting + mixed-mode DataLoader semantics) and unclear marginal value if the off-policy teacher branch is small in practice. Primary direction is a pure improvement within one branch.

## Synthesis Notes

The primary direction (continuous soft reweighting) is the smallest, lowest-risk change among the six and inherits all of the status-quo's response-level retry/discard machinery untouched. If the team wants to go further in one of the orthogonal directions, the natural composition is to wrap the soft-weight primary with one of the alternatives without conflict:

- **Combining with Alt-2 (rank-correlation gate)**: replace the current `consistency_ratio` (fraction of consistent adjacent pairs) with Spearman ρ to make the response-drop decision statistically interpretable, while still using the soft per-paragraph weight for kept responses. This drops the two-knob coupling between `TOP_PERCENT_RESPONSES` and `MASK_TOP_PERCENT_SEGMENTS` to a single (τ_keep, γ) pair.
- **Combining with Alt-5 (Bayesian / conformal)**: feed the posterior-violation probability into the soft weight directly (e.g., `w_i = 1 − P(violation_i | data)`) so the same machinery produces a calibrated continuous weight.
- **Combining with Alt-6 (curriculum routing)**: use the soft weight within the "mid consistency" branch only; the high-consistency and low-consistency branches still get vanilla OPD or teacher SFT respectively.
- **Alt-4 (cheap per-token proxy)** is the only direction that is mutually exclusive with the others at the data-cost level — if the K-fold rollout is replaced by a logit-derived proxy, the per-paragraph inconsistency score must be re-validated against the proxy, and the segment boundaries themselves become optional (per-token weights could be derived without any trigger-word segmentation).

The recommended sequence: ship primary first as a drop-in extension of `tools/process_reward_consistency_opd.py`, run the γ ∈ {∞, 4, 2, 1, 0.5} sweep against the existing binary baseline, then choose between Alt-2 (statistical interpretability) and Alt-6 (recover the teacher-SFT branch) for the next iteration based on which weakness shows up in the sweep.
